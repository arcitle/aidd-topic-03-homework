# Анализ исходного кода Investing Demo

## Назначение и технологический стек

Investing Demo — веб-приложение для просмотра каталога акций и котировок. Пользователь может просматривать акции и графики их исторических цен; зарегистрированный пользователь может добавлять, редактировать и удалять записи каталога. Есть REST API для операций с акциями. Данные о финансовых инструментах и ценах запрашиваются у Tinkoff Invest API. Celery предназначен для периодического обновления последних цен.

Основной стек: Python и Django 4.1, PostgreSQL, Django REST Framework, Celery с Redis в качестве брокера, Plotly для графиков, официальный клиент Tinkoff Invest. Интерфейс — серверные Django templates с включёнными в репозиторий Bootstrap CSS-стилями. Конфигурация проекта находится в `config/`.

## Структура проекта

- `config/` — настройки Django, корневая маршрутизация, WSGI/ASGI и настройка Celery.
- `dashboard/` — каталог акций: ORM-модель, формы, страницы списка/карточки/CRUD, REST API, интеграция с поставщиком котировок, фоновая задача и команда импорта.
- `user/` — формы и страницы регистрации, входа и выхода. Используется стандартная модель пользователя Django.
- `dashboard/templates/`, `user/templates/` — HTML-шаблоны страниц; `*/static/` — CSS.
- `dashboard/migrations/` — миграции схемы `Share`.
- `manage.py` — стандартная точка запуска административных команд Django.
- `requirements.txt` — Python-зависимости; `docker-compose.yml` описывает контейнеры PostgreSQL и Redis.

## Архитектура и взаимодействие компонентов

Приложение использует типичную Django MVC/MTV-структуру. Маршруты из `config/urls.py` направляют запросы в приложения. Представления в `dashboard/views.py` читают и изменяют модель через Django ORM, а для отображения используют шаблоны. `ShareListView` показывает каталог с пагинацией по 100 записей; карточка акции строит HTML-график посредством `dashboard.services.graph.get_graph`. Формы создания и изменения основаны на `ModelForm` для `Share`. Доступ к HTML-операциям создания, изменения и удаления ограничен проверкой аутентификации; при отказе пользователь перенаправляется на список.

REST-маршрут доступен по `/api/v1/shares/`. `ShareViewSet` реализует стандартные операции `ModelViewSet`; сериализатор преобразует поля модели в JSON. Для API заданы фильтрация по `name` и `ticker`, поиск по `name`, сортировка по `name`/`ticker` и пагинация DRF с размером страницы 100. В коде API нет проверки аутентификации или прав доступа, поэтому используются настройки DRF по умолчанию.

Сервис `dashboard.services.market_data` получает последнюю цену для FIGI через клиент Tinkoff. Задача `dashboard.tasks.update_last_price` перебирает записи акций, запрашивает котировку и обновляет цену и признак направления изменения. Celery autodiscover находит задачу, а расписание задано в `config/celery.py`; требуется запущенный Redis-брокер и worker (и beat для расписания). Команда `manage.py add_shares` загружает инструменты из Tinkoff и создаёт отсутствующие записи. Исторический график загружается при запросе страницы акции напрямую из Tinkoff API за последние 180 дней; история цен в локальной БД не хранится.

Схема потока запроса: браузер или REST-клиент → Django URL dispatcher → view/ViewSet → ORM → PostgreSQL; HTML-ответ строится шаблоном, API-ответ — сериализатором. Для внешней рыночной информации сервисы обращаются к Tinkoff API. Для фонового обновления Celery worker выполняет задачу через брокер Redis и сохраняет результат через ORM.

## Модель данных

В собственной бизнес-модели проекта определена одна сущность `dashboard.Share` (таблица акций):

| Поле | Тип / ограничения | Назначение |
|---|---|---|
| `id` | автоматически создаваемый BigAutoField, первичный ключ | Внутренний идентификатор записи |
| `figi` | строка до 255 символов, уникальная | Идентификатор инструмента у поставщика |
| `isin` | строка до 255 символов | Международный идентификатор ценной бумаги |
| `name` | строка до 255 символов | Название компании/инструмента |
| `ticker` | строка до 10 символов, уникальная | Биржевой тикер |
| `currency` | строка до 20 символов | Валюта котировки |
| `uid` | строка до 255 символов, уникальная | UID инструмента Tinkoff |
| `last_price` | Float, допускает NULL и пустое значение | Последняя сохранённая цена |
| `is_trend_high` | Boolean, допускает NULL и пустое значение | Признак роста относительно предыдущей сохранённой цены |
| `updated_at` | DateTime, `auto_now=True`, допускает NULL | Время последнего сохранения модели |

Связей между собственными сущностями нет: модели портфеля, сделок или истории котировок отсутствуют. Django также использует свои стандартные таблицы пользователей, групп, разрешений и сессий; бизнес-модель `Share` с пользователем не связана. Пользовательская регистрация создаёт стандартного Django-пользователя с email, переданным в качестве username.

## Обработка запросов и работа с БД

Для HTML CRUD применяются generic class-based views Django (`ListView`, `CreateView`, `UpdateView`, `DeleteView`); чтение одной акции реализовано отдельным `View`. `ShareModelForm` включает все поля модели. При регистрации форма проверяет совпадение паролей и наличие email, затем создаёт пользователя; вход выполняется через `authenticate` и Django session login. После успешного входа/регистрации выполняется переход к каталогу. Выход вызывается GET-запросом.

Доступ к PostgreSQL выполняется через Django ORM. Настройки подключения в `config/settings.py` указывают БД `investing` на `localhost:5432`, пользователя и пароль `postgres`; те же реквизиты заданы в Compose для контейнера БД. Redis доступен по `127.0.0.1:6379/0`. Внешний Tinkoff API использует токен `TINKOFF_TOKEN`, заданный в настройках.

## Основные библиотеки и внешние зависимости

- `Django` — web framework, ORM, шаблоны, сессии и встроенная аутентификация.
- `djangorestframework`, `django-filter` — REST API, сериализация, фильтрация и пагинация.
- `psycopg2-binary` — PostgreSQL-драйвер.
- `celery`, `redis` и `kombu` — фоновые задачи и брокер сообщений.
- `tinkoff-investments` — вызовы Tinkoff Invest API для инструментов, котировок и свечей; `tinkoff` также указан отдельно в зависимостях.
- `plotly` — построение интерактивного графика истории цен.
- `django-crispy-forms`, `crispy-bootstrap3` — оформление Django-форм.
- `black`, `isort` — инструменты форматирования и сортировки импортов.
- Остальные зависимости в `requirements.txt` включают транзитивные компоненты Celery/gRPC и вспомогательные библиотеки.

## Замечания по фактической реализации

- В `get_last_data` и `get_graph` цена берётся только из поля `units` ответа API; дробная часть `nano` не учитывается.
- В расписании `add-every-5-min` в действительности указано `10.0` секунд, а не пять минут.
- В настройках включён `DEBUG`, `SECRET_KEY` и токен API оставлены пустыми, `ALLOWED_HOSTS` пуст. Для полноценного запуска нужны корректные настройки окружения и доступность PostgreSQL, Redis и Tinkoff API.
- `ShareModelForm` открывает для редактирования все поля сущности, включая внешние идентификаторы; API предоставляет полный CRUD без явных ограничений доступа.
- График строится при открытии карточки запросом к внешнему API; локальные временные ряды и отдельный механизм кеширования в проекте не реализованы.
